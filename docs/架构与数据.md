## 分层

Vue 单页负责交互，不把账号凭证存入 localStorage。Nginx 代理同源 REST / 健康检查，应用 Cookie 承载服务器会话，CSRF 保存在前端内存。Spring Security 认证；LiveAccess 在每次请求校验账号启用和密码散列变更；AccessService 按最新角色检查权限。

ExpenseService 负责单据、预算、附件和付款事务。AdminService 只处理登记的管理类型。客户端金额、状态、岗位与数据范围都重新校验，客户端不能设置申请人或部门。

## 数据表

| 表 | 用途 |
| --- | --- |
| department / account / access_role | 部门、账号、角色；账号引用有效角色和部门 |
| permission / role_permission / nav_menu | 权限目录、角色权限、导航 |
| dictionary_entry / system_setting | 双语类别、有限参数 |
| expense_budget | 唯一部门＋类别＋月份；额度、预留、费用整数分 |
| expense_case | 申请／报销、版本、状态、岗位、金额、唯一关联申请 |
| expense_line | 明细日期、金额、开具方、编号、全局唯一活动凭证摘要 |
| expense_evidence | BLOB 原始文件、摘要、类型、大小、冻结状态 |
| expense_event | 不可改流转事件；SUBMIT 保存单据／明细／附件摘要快照 |
| expense_payment | 付款原记录、冲销时间／人员／原因；单据内编号唯一 |
| expense_command | 单据＋操作者＋幂等键唯一，命令摘要检查重用 |
| audit_event | 操作者、动作、对象、部门和时间，不存请求密码 |

数据库迁移位于 backend/src/main/resources/db/migration，V1 表与约束，V2 外键与范围索引。所有业务表保留外键，既有提交记录不级联删除。JPA ddl-auto=validate，禁止应用自动改表。

## 状态和资金口径

申请：DRAFT → MANAGER → FINANCE → APPROVED → CLOSED。申请可退回 REJECTED，申请人修改并重新送审；可按规则取消 CANCELLED。撤回只在 MANAGER 返回 DRAFT，但已送审历史继续受保护。

报销：DRAFT → MANAGER → FINANCE → APPROVED → PART_PAID → PAID。付款登记累计到全额才 PAID；冲销回到 PART_PAID 或 APPROVED。退回／取消按岗位、版本、是否已有付款约束执行。

预算占用为预留＋已批准报销，不等于实际付款。申请获批加预留；关联报销获批释放全部申请预留并加实际费用；关闭申请释放余预留；未付款批准报销取消释放费用。付款和冲销不改变费用占用。已授权超预算允许占用大于额度。

## 一致性与限制

写业务先锁部门行，再刷新单据，随后读取预算和执行版本校验，所有同部门费用写入与预算更新按同一顺序序列化。单据 @Version + changeCount 防止丢更新；预算 @Version 防止旧额度覆盖。命令在事务内保存摘要，同一账号同一单据完全相同重试返回当前详情，改变内容拒绝。唯一约束防止活动凭证、关联申请与付款编号竞争。

每单金额与预算额度最高一亿元，整数分运算。详情附件字节不进入 JSON，只能经授权下载。汇总／待办最多 10,000 条授权记录，超出明确拒绝；目录有 10,000 上限。当前是单应用实例会话与登录限流，未实现集群会话或分布式限流。附件数据库存储适合学习与小规模评估，需要按实际规模制定容量和对象存储方案。
