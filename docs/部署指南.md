## 本机运行

Docker Engine 与 Compose v2，Python 3，端口 8101。运行 python3 scripts/init-env.py，确认 .env 权限仅当前用户可读。docker compose config --quiet，docker compose up -d --build --wait。系统首页 http://127.0.0.1:8101，健康检查 /actuator/health。空库管理员 admin，密码为 .env 的 ADMIN_PASSWORD，没有固定密码。

DATABASE_PASSWORD、MYSQL_ROOT_PASSWORD、ADMIN_PASSWORD 必填；数据库和管理员密码相互独立。WEB_PORT、BIND_ADDRESS 可覆盖，默认仅本机。现有卷上的管理员密码不会被初始化覆盖；更改数据库密码不能仅更改 .env，应按数据库维护流程同步账号。禁止提交 .env、备份、真实凭证或日志。

## 外部数据库开发

后端 Java 21 / Maven 3.9，前端 Node 24.19+。自行建立空数据库和专用账号，通过 DATABASE_URL / DATABASE_USER / DATABASE_PASSWORD / DATABASE_CATALOG 指定。默认库 zhuatech_expenseflow，默认用户 expenseflow。MariaDB JDBC 驱动连接 MySQL，配置目录映射和 UTC 会话，时区业务参数默认 Asia/Shanghai。生产远程数据库应验证证书，不直接沿用本机 Compose 的 sslMode=trust。

使用 mvn spotless:check test spring-boot:run；前端 npm ci && npm run dev，Vite 将 /api 代理到本机 8080。运行版本与命令见 README。

## 升级与备份

1. 停止写入，做 MySQL 一致性备份，包含业务表、附件 BLOB 与 flyway_schema_history。
2. 在隔离库恢复备份并演练迁移、登录与审批，确认升级兼容性。
3. 新版只能增加新的版本化迁移，不改已执行脚本。docker compose build 会执行单元／集成测试和前端检查。
4. 启动后检查健康、Flyway 历史成功标记和费用／凭证查询。变更后端会导致会话重建，业务仍在卷内。
5. 迁移不可逆时回退旧镜像不足以恢复，应按演练结果恢复整库，不删除共享数据卷。

默认 docker compose down 保留本项目 mysql-data。down -v 删除数据库和全部附件，仅用于独立且可丢弃的验收环境。备份可能含财务、人员和凭证数据，应加密、限制权限并验证恢复。不要把备份上传到公开 Git。

## 正式接入

商业使用先获得书面授权。部署方提供有效 HTTPS、域名、备份策略、网络与运维控制。上层反向代理必须正确传递协议与 Host；COOKIE_SECURE=true 仅在 HTTPS 下使用。保留数据库和后端网络隔离，按用途配置请求大小及附件扫描。默认系统为单实例，不声称具备高可用或生产认证。

## 排障

docker compose ps 检查健康，docker compose logs --tail=100 backend 查看错误。依赖下载失败应检查网络后重新构建；构建不能跳过测试。迁移失败核对数据库权限和版本，禁止直接修改历史记录绕过失败。端口占用覆盖 WEB_PORT，不停止其他项目。凭证代理最大请求 6 MiB，后端单文件 5 MiB；错误优先检查类型、大小和单据版本。
